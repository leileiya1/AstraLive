# 12 — P8：TTS 静默丢字的修复与方案选择（2026-10-22）

## 问题（比最初报告的更大）

本机及所有真实路径（`main.py`、`session_binding.py`，包括即将进行的 GPU 实测默认模式）使用的 TTS 都是 sherpa-onnx VITS `zh_CN-xiao_ya`。其词表 68,012 项，**没有任何拉丁字母**，引擎对不认识的字符只打日志 “Ignore OOV” 后跳过。真实引擎探测结果：

- 字母：“纯棉T恤有S、M、L和XL尺码” → “纯棉恤……XL尺码”；“USB-C、5000mAh、1.2kg” 丢掉 9 个字符。
- **影响含义的符号**：`%`（“打5折50%优惠”读成“五十优惠”）、`+`（“买2+1”读成“买二一”）、`~`（“满100减20~30”读成“二十三十”）、`¥` `℃` `×` `㎡` `/` `&` `#`。对带货数字人而言，读错价格和折扣比漏读字母更严重。
- 只影响停顿的标点（引号、括号、《》、连字符）被跳过不影响内容。

## 方案比较

| 方案 | 结论 |
| --- | --- |
| 1. 继续给 `spoken_sizes()` 加句式 | 否：每种新写法都要新正则，漏掉的仍是**静默**丢失 |
| 2. 通用“读法规范化 + 按模型自身词表核对” | **采用**：所有字母、单位、含义符号都有读法；`uncovered()` 让“静默丢字”可测量 |
| 3. 生产改用中英混读 TTS（CosyVoice） | 方向正确，但仓库中 CosyVoice 只是可选的声音克隆桥，未接入默认路径；留到 GPU 实测时评估 |

原则：**已提交、已哈希的答案正文不变**，只改变引擎朗读的形式（与原有 `spoken_sizes()` 相同性质）。

## 实现（受保护文件 `runtime/app/real_tts.py`，按所有者授权登记）

`spoken_text(text, pronunciations)` 的顺序：
1. 原 `spoken_sizes()`（不变，原有测试含义不变，如“30 S、500 ML、20 M”不当作尺码）；
2. 可配置读音表（运营/商品数据可为品牌词提供读法，如 iPhone→爱疯；按词边界匹配）；
3. 含义符号：`¥99元`→99元，`$20`→20美元，`50%`→百分之50，`20~30`→20到30，`#12`→12号，`元/件`→元每件、`A/B`→A或B，`+`→加，`2x3`/`×`→乘，`℃`→摄氏度，`㎡`→平方米，`&`→和；
4. 数字+单位：毫升、升、米、厘米、毫米、千克、克、秒、分钟、小时、毫安时、瓦、伏、安、千瓦、GB/TB/MB；
5. “T恤”→“踢恤”；
6. 其余字母串按中文字母名逐个读（S/M/L/X 与 spoken_sizes 一致）——不理想但**永不静默**；建议为常用品牌词配置读音表。

另有 `lexicon_characters()`、`uncovered()`、`PROSODY`，以及 `pronunciations` 构造参数（类级默认 `None`，兼容绕过 `__init__` 的既有测试）。

## 验证

- `runtime/tests/test_tts_pronunciation.py`：7 项。包括逐句期望读法、尺码语义不变、读音表优先且按词边界、26 个字母都有读法，以及**真实引擎 stderr**：修复前会丢内容字符，修复后被丢的只剩 `PROSODY` 停顿符。
- 现有真实 TTS 集成测试（`RUN_REAL_TTS_INTEGRATION=1`）3 项通过；首块 75 ms、整句 166 ms。

## 仍然存在的局限

英文单词在没有读音表时只能逐字母读；数字由引擎自带的 number.fst 处理（未改）；声调/多音字仍由模型决定。真正自然的中英混读需要阶段 7 评估 CosyVoice 等模型。
