## Receiver local Stop ordering and linearization (A/B/C repair)

A successful ReceiverStop is an irreversible tombstone for the exact logical runId in that Guardian admission domain. It is effective independently of Backend Stop delivery or commit. The two operations remain separately orchestrated in their original order; neither can be delayed/reordered to conceal an unsafe local interval. A stopped Run cannot restage the same registration or reopen from FENCED/CLOSING/UNKNOWN using old ticket, Grant, Permit or a fresh Authority snapshot. An unrelated Run tombstone does not close the current Run. A fresh physical context does not erase an old Run tombstone or migrate its Grants; post-Stop business admission requires the already-defined new business identity and trusted fence/registration path.

Normal unit drain is different: Finish closes only that execution, increments the local barrier revision, clears its active slot and returns STAGED_CLOSED without a Run tombstone. Unit2 may then consume its own Grant after Backend trusted drain under the same legitimate parent registration, Attempt, Turn and Generation. Existing media clocks/outer ordinal continue unchanged.

| Operation | Current local admission and final commit |
| --- | --- |
| Consume | New winner only in STAGED_CLOSED with no active execution, no Run tombstone and exact live staged registration. ACTIVE_UNIT permits only same-Grant duplicate reconciliation (never a true ACK); Backend still enforces full nonce/channel conflict semantics. FENCED/CLOSING/UNKNOWN deny before RPC. Fresh Commit ACK and deny-replay fsync do not themselves activate a slot: final proof returns, all guards are rechecked, then activation and first ACK enqueue form one local critical section |
| Renew | Only known ACTIVE_UNIT, exact execution/Artifact/hash, authenticated Runtime process/channel and registration. Authority read is outside the local lock; final proof installation/reply is guarded under that lock. Never commits a Grant or creates TTS eligibility |
| Media | Same ACTIVE_UNIT/proof checks plus current continuous sequence. After the final Authority RPC and any hook, final guard and actual bounded nonblocking media handoff are one local critical section. No sequence or accepted counter advances on rejection |
| Finish | Same active identity and current proof. Trusted Observer executes outside the lock; its genuine evidence does not override a later Stop. Final guard, evidence acceptance, execution closure, slot clearing and revision increment are one critical section. Stop winning first prevents STAGED_CLOSED reopening |

Guardian's local synchronization domain is distinct from Backend's SQL run-lock domain. It uses one local mutex or equivalent serial actor/atomic gate shared by Stop, Stage, Consume final activation/ACK, Renew proof commit, Media final handoff, Finish closure and Guardian Restart. Capture the current Guardian incarnation/barrier revision plus immutable registration and execution identity under the gate; release it before Authority RPC, fsync, Observer or other external/blocking work; reacquire and compare before using each result, and again in the final commit section. Check Run tombstone, legal state, exact parent registration/hash/revision, run/epoch/Session/output binding/Generation, authenticated Runtime principal/incarnation/channel, current execution/Artifact/hash/Grant and current proof deadlines. Original Grant deadline additionally applies to first Consume; it remains irrelevant to already-consumed ongoing output.

No external callback, remote I/O, file fsync, network delivery, blocking sink write, drain wait or unbounded retry is allowed inside this local gate. Stop never waits for those operations; at most it contends with one bounded local commit. The final local check and the actual admission action cannot be separated by an await/callback/unlock. In the reference model, returning the positive ACK and incrementing media_count are the linearization points for nonblocking ACK enqueue / media handoff. The bounded linearized diagnostic deque contains metadata only, never PCM or executable tickets. Production adapters must provide a corresponding bounded nonblocking acceptance edge; a blocking publisher/decoder/transport must do its wait outside the gate and recheck at its irreversible delivery edge. Enqueuing an unchecked work item and later sending it after Stop is forbidden. No new unbounded media queue is introduced.

If Stop wins the local gate first, every later ACK/handoff/renew/finish for that Run is rejected. If a media handoff or first ACK wins first, that event is ordered before Stop; Stop then closes subsequent eligibility. This cannot retract media already handed off before Stop or prove audience audibility. An ACK enqueued before Stop but delivered afterward is not a renewed authorization; Runtime still applies its pending nonce, original deadlines and final proof checks, and the Receiver accepts no further output for a stopped Run. Cross-machine Stop propagation retains the existing short-Permit/watchdog limitation; this repair addresses the strictly stronger case where local Stop has already happened.

Backend Commit may win while local Stop wins before Guardian ACK. Backend's immutable unique consumption latch is retained forever under existing retention rules; Guardian records UNKNOWN in its separate denial/audit projection and never activates it. If the positive commit reply is itself lost, only existing metadata reconciliation is possible. Stop/Restart clears executable local state but keeps non-executable audit; a later reply may append an UNKNOWN audit record but cannot arm it. No rollback/delete of the latch, ticket reissue, cached true response or UNKNOWN-to-active transition is permitted. A same-Grant exact retry may return false/null knowledge only when otherwise locally admissible; stopped/closed runs reject outright. An in-flight revision mismatch is CONSUMPTION_UNKNOWN; a known Run tombstone at initial admission is RUN_STOPPED. Finished old units use STALE_EXECUTION; identity conflicts and expiry retain the existing error codes.

This is a safety repair of previously mandated Stop precedence, without wire-field changes: durable-live-2 / receiver-1 version tokens and all ticket/hash/Grant semantics are retained. The changed normative digest requires new owner ACKs; previous fixed-SHA ACKs remain historical only. Production v2 is still disabled and no unapproved protocol implementation is introduced. Tests use genuine fixture bootstrap exchanges, deterministic RPC/fsync/Observer pauses and local commit logs; they do not prove real PostgreSQL, OS/IPC, physical sink fencing, crash-fsync durability or a latency SLA.
