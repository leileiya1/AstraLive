# durable-live-2 candidate — Incremental answer contract

Status: PENDING OWNER ACK; governed by CCR-ADL-001. Existing run/Turn/dispatch/checkpoint semantics remain; this section defines COMMENT answer preparation and the versioned changes only. Runtime never writes SQL. Go is the sole writer, reached by registered RUNTIME_JOURNAL service identity over protected HTTP. All new objects are closed, exact UTF-8 hashes and safe integers; scope derives from command/run plus authenticated producer, never JSON permission.

## Identity, hashes and atomic storage

One COMMENT has one run/Turn/attempt/Utterance/immutable command, one answerId, at most32 AnswerArtifacts. An artifact identifies a **complete semantic speech unit**, not a new SpeechSegment or Turn. Units are contiguous sequence1..N, maximum240 Unicode characters and estimated≤6 seconds each; answer total≤2000 characters, wall time≤min(command deadline,30 seconds from answer preparation start). All persisted artifacts/receipts are immutable.

`requestHash` is always the original accepted command's canonical hash (question). `answerTextHash` is SHA256 of that unit's exact UTF-8 answerText. `artifactHash` hashes canonical entire AnswerArtifact excluding only artifactHash, including version, full identity, answerText/hash, productId/snapshot version, ordered factDependencies (at most one dependency per kind/product), semantic boundary and previousArtifactHash. No whitespace/NFC rewriting. First previousArtifactHash=null; later points exactly to previous unit. Same `(commandId,answerId,sequence)`, artifactId or scoped idempotencyKey with any different descriptor/hash/body/version/dependency → ANSWER_CONFLICT. Correlation requestId and expected revisions do not change the artifact identity. Retries reuse the stored descriptor and key. Alias readback is allowed only if that alias is atomically reserved to the same exact descriptor and original receipt before returning success. Scope is `(tenantId, ownerId, runId, commandId, operation, idempotencyKey)`; no successful alias lookup may leave an unbound key available for a later different Artifact. A conflicting existing binding is rejected even when the Artifact itself already exists. Correlation or expected revision changes do not rebind a key.

`JournalPrepareAnswer` atomically writes artifact body/hash, productSnapshotVersion, complete factDependencies, chain relation, immutable prepare receipt and answer stream CAS. First prepare creates the answer header and increments inbox revision ACCEPTED1→ACCEPTED2; response names inboxRevision=2 (used for START) and answerRevision=1. Later prepares require an OPEN answer, this same live producer's STARTED command, and the immediately previous unit either STARTED (one lookahead) or trusted DRAINED (empty playback window). DRAINED must reference an applied, registered all-required drain proof; a state string alone is insufficient. PREPARED/UNKNOWN/INTERRUPTED predecessors cannot be bypassed. Stale prepare-vs-drain CAS losers reread and retry the same descriptor/key and increment **answerRevision only**. Duplicate identical prepare returns the original receipt/revisions, increments nothing and never contains a grant. Client queries current revisions before a different mutation; an old prepare receipt does not certify current state. A first prepare may also be the final whole one-unit answer, but there is no separate weaker whole-answer mode.

Auth, run/Room/Session ownership, producer binding, revision compatibility, current epoch, active lease, nonexpired Provider Binding, command deadline, unsealed executor, current product snapshot and authoritative facts are checked **before duplicate lookup**. Prepare permits inbox ACCEPTED for unit1 and STARTED for later units; after seal only identical authorized readback is possible, never new text. Snapshot/fact mismatch rejects, no partial writes and no silent regeneration under the same identity.

## START and continuation

1. JournalAccept durably accepts the immutable question command; read-only LLM/Tool generation may begin. It does not permit TTS, GPU or publication.
2. Receive one complete safe answer unit, validate its actual assertions and tool facts, compute hashes, submit JournalPrepareAnswer. Neither generated PCM nor a free text prompt is a preparation receipt.
3. Acquire an artifact-bound Output Permit; JournalStart receives artifactId/hash + expectedInboxRevision + expectedAnswerRevision. In one transaction it independently revalidates facts/identity/lease/binding/permit, CASes command ACCEPTED→STARTED **once**, CASes unit1 PREPARED→STARTED and mints its one-shot answerGrant. A SCRIPT START sends null answer fields and retains exact-script behavior.
4. Only the first successful response carries startAuthorized=true and unit1 grant. Duplicate, lost response, request retry or query never returns an old true authorization or grant. Missing START 200/202/ACK means no TTS/effect, query then UNKNOWN as appropriate; no second command, attempt or Turn. ACKed START with expired local permit also has no effect.
5. While one unit plays, prepare at most one following unit using LLM backpressure. After current unit's genuine all-required local drain, `JournalConfirmAnswerSegment` records ranges against its artifact. Only then can `JournalStartAnswerSegment` CAS the next PREPARED unit→STARTED and mint one grant. It rechecks authority/facts/permit at each grant. Repeated grant calls return segmentStartAuthorized=false, grant=null; lost grant ACK is UNKNOWN, never a second grant.
6. TTS reads only the committed artifact exact body checked against answerTextHash and artifactHash. Each grant is consumed once by the same live executor; OutputGate checks the immutable consumed execution binding, active artifact, command/attempt/producer/epoch/Generation and current permit/fact proof at every handoff. It does not treat a consumed Grant's original expiresAt as the continuing output deadline. It must reject future/previous unit media. No TCP packet/PTS/credit fields are changed; this is outer adapter metadata.

One-shot grants are **not** generic cached idempotent responses: never cache/replay true through dl05_requests. Prepare/confirm/seal receipts are safely idempotent, authorization is not. QueryAnswer only returns current revisions, immutable artifacts and execution states, no grant or authorization boolean. A restarted/reconnected producer may inspect authorized state but cannot reconstruct a started task or claim an already STARTED artifact. Different producer or epoch must fail closed. Existing conservative UNKNOWN/manual policy applies even when later units are known prepared.

## Grant consumption and ongoing execution (four separate lifetimes)

| Object | Lifetime / authority | Renewal rule |
| --- | --- | --- |
| AnswerGrant | Immutable one-shot permission to **first consume/start this unit**. `authorizationScope=UNIT_START_ONCE`; `issuedAt <= consume-complete < expiresAt`. Its initial permitId/factObservationId/factValidUntil pin issuance proof, including the bootstrap Generation mapping | Never extend, reissue, copy true authorization from cache, or reacquire via Query. A new Permit/Observation cannot rescue an unused expired Grant |
| AnswerExecutionBinding | Receiver's immutable once-consumption latch: run/session/command/attempt/answer/artifact/hash + producer/epoch/Generation + grantId/executionId + Guardian incarnation + consumedAt | No rebinding or recreation after process restart, UNKNOWN, retired Generation or fence. ACTIVE execution may continue with fresh proofs; Grant remains CONSUMED forever, not EXPIRED after its initial deadline |
| Current Output Permit | A distinct short-lived proof, at most1second including existing conservative local margin, checked for the exact same execution identity at every handoff | May have a **new permitId**; cap by current fact proof, run lease, Binding and command deadline. Replacing a proof does not invoke START, consume a second Grant or start TTS again |
| FactObservation | Append-only same-snapshot/source/value verification; validUntil at most2seconds from trusted verification | May have a **new observationId**, with full Artifact/attempt/producer/epoch/Generation binding. Original descriptor and older observations stay unchanged. Current handoff must reference a currently valid observation through its current Permit |

There is no new Backend RPC in this repair. Consumption is the existing once-only receiver boundary made explicit: the same live Runtime and registered Guardian adapter must latch the AnswerExecutionBinding **before TTS**, with the one-shot handshake/acknowledgement completed before the original nonextendable consume deadline. An isolated Guardian uses authenticated private IPC and its trusted grant/permit authority reader; never trust Runtime's self-reported TTL/time or JSON alone. This is a required post-approval v2 adapter change, not a claim that PR10 already implements it. If consumption ACK is lost/late, or either side loses the latch, mark UNKNOWN/fence; Query and new proofs cannot restore the right to first execute. The oracle's synchronous begin_tts models a completed once-consumption boundary. Legacy guard-only fixtures model that same consumption at their first handoff.

The original Grant's bootstrap proof must still be valid at first consumption, so a renewed proof cannot change its Generation or resurrect its deadline. After completed consumption, those initial proof IDs and expiry are audit references. Select the **current** Permit and its current Observation, verify the same immutable binding, and keep bounded renewal running while waiting for first PCM and throughout a2–6second unit. No second global START, continuation grant, Turn, Utterance or TTS invocation occurs. `examples/grant-renewal-trace.json` consumes at100ms, retains the800ms Grant unchanged, renews current permits beyond1second and facts beyond2seconds, and reaches trusted drain at5seconds on one execution.

A proof lapse immediately blocks output. If the receiver has merely paused handoff without retiring the still-known execution, a fresh authoritative **same-value, same-binding** proof can continue that already consumed execution; it cannot start it again. If the watchdog has fenced/retired it, a process restarted, authority was lost, or state is UNKNOWN, it cannot resume with new proofs. Stop/old Epoch/expired Binding or run lease always wins. Backend may initially know only that a Grant was ISSUED/may have been consumed; absence of a consumption report is never NOT_EXECUTED. Registered receiver/drain evidence can fill audit knowledge, never authorize media. Any required persistent receiver state/SQL sidecar is owner implementation work; Python Runtime still never writes the business DB.

## Prepare and Drain receipt identity

Prepare key/alias binding, immutable descriptor verification and original receipt lookup/creation share the same short transaction and run/answer lock. The alias table has a unique scoped operation/key and an immutable descriptor/hash/receipt FK. If the same key is presented for another Artifact, reject ANSWER_CONFLICT before any success response; no Artifact/receipt/CAS change. A concurrent winner fixes the binding and the loser either returns the same descriptor's receipt or conflicts.

Drain uses `AnswerDrainIdentity`: the complete closed JournalConfirmAnswerSegment request **plus operation name**, excluding only `requestId` and `expectedAnswerRevision`. It includes schema/revision, tenant/owner/run, command/attempt/session, original requestHash, producer/epoch, answerId/artifactId/artifactHash, scoped key and complete canonical evidence (including sink generations/ranges and proof refs). Server resolves those refs to trusted observer/consumption records for this Artifact; equal evidence copied to a different Artifact is not a proof. Same key with a changed answer, Artifact, Hash or evidence returns ANSWER_CONFLICT. A duplicate same identity returns the original DRAINED receipt without reapplying projection or trusting the caller's current state. Response echoes answerId/artifactId/artifactHash and drainIdentityHash. New keys for already drained units are not aliases; only the original matching receipt is replayable. Unit1's receipt cannot report success for Unit2 while Unit2 remains PREPARED.

## Facts and expiry

Answer factDependencies describe assertions in the **answer**, not the input question. PRODUCT_DETAILS (name/description/material snapshot) and price/currency/stock/availability/size options use current authorized Product Tool projection; unsupported SKU/promotion/delivery claims are rejected without an authoritative source. An empty dependency list is permitted only when the trusted assertion classifier proves there are no product assertions. Product context must still match the command/active plan; unavailable data cannot be converted into an invented answer. Python's `complete` or fact declaration alone is not authority.

Artifact metadata is immutable even if old validatedAt expires. Eligibility can be refreshed **only** by a new append-only FactObservation confirming identical sourceVersion/valueHash and current productSnapshotVersion, with verifiedAt/validUntil≤2 seconds from authoritative verification. A changed fact cannot be refreshed in place; refuse the unit and stop/fence the answer. Remote Tool/LLM calls occur before the SQL transaction; inside the short transaction recheck SQL product version/fact values or the pinned authority revision, observation hash and DB time. If external facts cannot be checked for races against a stable authoritative version, fail closed. Never hold SQL locks across LLM/TTS/GPU/HTTP.

START and every continuation use fresh observations. During playback, artifact-bound permit renewals revalidate the same assertions and cap their expiration by fact validity, command deadline, run lease and Binding expiry; existing permit lifetime≤1second and safety margin remain. No handoff after the earlier of permit/fact expiry, even if PCM is buffered. Missing fresh proof or changed product stops renewal and closes output; it cannot keep reading stale COMMENT facts. Already transmitted media cannot be retracted. Emergency Stop/expiry may interrupt a unit; the prohibition on incomplete speech concerns deliberate scheduling of unfinished grammar, not an impossible promise to finish speaking after permission is revoked.

## Bounded streaming and semantic safety

No LLM EOF gate before unit1. No TTS of token fragments. Use complete self-contained sentences or authoritative Tool fact sentences; do not accept a prefix conditional, split number/price/unit/size, or truncate at bytes/time/length. Legacy sentence_stream is reusable as a token/boundary source, but its length fallback and first comma alone are **not** a semantic proof. Agent3's conservative validator must hold a dependent clause until its full meaning is available; over240-character indivisible text is rejected/cancelled, never cropped. A product assertion must agree with current facts before preparation.

At most one LLM task per command, one active media unit plus one prepared lookahead, one pending prepare RPC. Backend rejects a third undrained unit with ANSWER_WINDOW_FULL. Existing token queue≤8, slices≤64 characters; new assembler≤240 characters, provider event frame≤16KiB, request body≤256KiB. Pull/async backpressure reaches the provider; cancellation on Stop/epoch/expiry/limit/error closes upstream tasks and releases only owned buffers. Do not collect a full answer or launch concurrent GPU inference to hide latency. Persisted audit can contain at most32 bounded units/2000 total characters; it is not an unbounded media queue.

All units stay in the same COMMENT Turn and fairness/TTL accounting. Per-unit drain never Yield/COMPLETED the Turn, never advances script cursor, never creates another comment reply. Only the existing explicit Stop/operator/fence rules can break the Turn. No automatic fallback new answer after partially speaking; abort with evidence/UNKNOWN.

## Seal, completion and recovery

At LLM EOF, `JournalSealAnswer` commits final count, finalAnswerTextHash=SHA256(concatenation of exact unit texts, **no separators**), and manifestHash=SHA256(canonical ordered array of `{artifactId,sequence,artifactHash}`) after verifying the entire stored chain. EOF is required for **completion**, not for initial speech. Seal may occur while the last prepared unit still awaits playback; it grants no media. Duplicate identical seal returns original receipt; differing manifest/count/text hash conflicts. No new prepare after SEALED.

AnswerStream OPEN→SEALED→COMPLETED; no OPEN→COMPLETED. Unit PREPARED→STARTED→DRAINED, with one-shot grants; UNKNOWN/INTERRUPTED follow explicit evidence. Global attempt LOCAL_MEDIA_DRAINED/COMPLETED requires SEALED manifest, all units DRAINED with contiguous all-required sink ranges, no unknown grant/tail, and existing CONTROL business commit. Per-unit ranges use the existing continuous sample/PTS clock; neither reset nor fabricate audio positions. LOCAL_MEDIA_DRAINED is not remote audience audibility.

Crash before prepare commit: retry the identical descriptor, no TTS. Prepare ACK lost: query/retry identical descriptor, no grant. START or continuation ACK lost: do not execute; same command remains started/ambiguous and must not be re-authorized. Crash after some drain: preserve prefix evidence; never replay prior units or allocate a new Turn automatically. LLM error or missing seal: cannot complete just because queues are empty. STOP/old epoch/expired binding rejects prepare, start, continuation and renewal before receipt lookup; CONTROL may archive late historical evidence without reauthorizing media. Python has no DB credentials or direct SQL writer path.
