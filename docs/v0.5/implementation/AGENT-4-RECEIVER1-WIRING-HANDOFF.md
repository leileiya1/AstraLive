## Trust boundary and exact ordering

1. Trusted Backend deployment supplies already-authorized Room/Run/Session/Provider Binding/command identity to `StartManaged`. It starts a dedicated executable with explicit allowlisted environment, a fresh principal/incarnation/credential and Guardian signing key. Backend DB/provider/RTMP secrets are not inherited in env/argv. Guardian key only goes to Guardian's anonymous FD; Runtime gets neither Guardian nor CONTROL credential. Native UID/PID/birth are independently read by the Go supervisor, and parent/child are rechecked by the Python loader. This is not code-image attestation or Linux isolation proof.
2. `NewControlChannel` creates a distinct credential for the co-located Registrar's actual process. Only its hash/process/scope goes into Guardian deployment metadata. `ProducerProvision` likewise carries Runtime verifier metadata, not the reusable secret.
