## Canonical evidence and required hash freeze

A independently archived a28a409 and ran six Go/Python vectors against the actual Canonical/TimelineCanonical implementations; accepted/rejected values and SHA256 match exactly (result.json). Nested JSON-safe identity/provenance/integer telemetry can be hashed. Every float, including 1.0, is rejected. Generic nested legacy int63 is rejected; only current typed Timeline proof paths permit it. Adding another nested stagingIdentity path does not inherit a worker-number exception.

Freeze full canonical object projections independently for StageBegin request_fingerprint, StageProduced descriptor_sha256, commit_proof_fingerprint and pose-proof fingerprint. Do not invoke command Fingerprint for these: it deliberately filters command fields and would omit standalone identity/provenance. Use existing strict Canonical+SHA256 and exact UTF-8 encoding, lower-case hex with explicitly specified sha256: prefix policy. Freeze required/null/absent fields, array order (sink set canonical sorting vs sequence arrays), valid Unicode/UTF-8 and duplicate-key rejection at inbound decoding, exact schema revision and domain discriminator. No loose float conversion, EventHash, platform json.dumps defaults, whole mutable message or Auth token in hash.

All descriptor/identity/limits/resource numbers must be integer counts/bytes/microseconds with field-specific nonnegative/positive safe bounds; durations/ratios use exact integer numerator/denominator pairs, not seconds/MB floats. Make live lease_age/resource/status counters and nonce explicitly outside immutable descriptor hashing, or freeze a single Produced snapshot that every retry returns byte-equivalently. Observed peak counters are telemetry, not proof of physical sink consumption or authorization. StageBegin chosen/requested lease and limits need distinct immutable field names and explicit selection/hash coverage.

## Integer domains and compatibility

1.2 staging workerGenerationId can use 1..9007199254740991 as proposed. Business runEpoch/timelineEpoch/generationId remain separately safe positive integers. Keep original 1.1 int63 Worker semantics and existing precise typed Timeline paths: proof.identity.workerGenerationId; proof.descriptor.workerGenerationId; proof.commit.identity.workerGenerationId; proof.commit.descriptor.workerGenerationId; proof.sinkReceipts[index].identity.workerGenerationId. No arbitrary key-name wildcard or broad int63 permission. New nested staging identity follows safe bounds; do not expand typed paths without a separately reviewed DTO/vector change. Ready unused highest_generation_id=0 is negotiation telemetry, not a valid attempt ID. A hash accepts signed safe integers generically: field validators must separately enforce positive epochs, generation, sample/range values and rational denominator.

## A proof references and authorization

Freeze actual existing ledger keys, not undefined commitId/receiptId: commit table commandId plus session/run/timeline/segment/attempt/generation tuple, source/output identity, exact output interval/rate, required/optional sinks. Installed proof reference should name operation=COMMIT_INSTALLED, existing receiptSeq and observationHash, expected/applied timeline revision, and installation ACK. A installed row must be ELIGIBLE with installed_at set, never PENDING_INSTALL. Caller revalidates current authenticated A ownership/lease/barrier at admission/publication boundaries; a cached receipt, opaque stageId or Worker auth is no fresh authority.

A StageProduced descriptor and B frozen timeline-ready descriptor are different objects. Freeze where the immutable staging descriptor/hash is carried in B/A descriptor, its equality and persisted binding to attempt/text/productVersion/output PCM. Hash covers exact staged bytes/provenance, while existing A descriptor contentHash/textHash/factVersion/sampleCount/requiredSinks retain their existing meaning. Source PCM16kHz and output timeline count/rate must be mapped explicitly; never overwrite the existing output hash/sample fields with source counts.

Current A sink receipts persist final SegmentCompleted ranges; the contract must not invent SQL receipt IDs/revisions for each live partial B watermark. B must define how existing SinkReceipt evidenceRef, sink incarnation, media/range/identity, local revision and canonical proof map to StagePoseConsumed. State explicitly whether a partial pose proof is transient B evidence under durable installed A commit, or a new durably journaled observation requiring A-owned schema/API work. Do not claim partial progress durable just because installation is durable. Worker never queries SQL independently. All required audio AND video ranges and captured sink set must be covered; optional identities cannot weaken them.

## UNKNOWN and lifecycle boundaries

STARTED stays nonreplayable; stage storage/native cleanup/pose ACK do not authorize speech replay or recovered run. Same-process status is read-only, not new generation permission. Missing ACK/disconnect/lost terminal record is UNKNOWN; exact prior idempotent reply may reconcile only its proved operation, not imply unexecuted media. StageReleased cannot create SegmentCompleted or audience-audible proof. New Worker incarnation must correspond to explicit retirement of old exclusive Worker ownership/native activity, not merely regenerated workerEpoch. Separate confirmed consumed-prefix evidence from safe cleanup evidence. Keep unresolved tail/cursor and binding reservation until reviewed disposition; no automatic downgrade or generic receipt completed claim from storage success.

These points constrain DTO/hash/reference freeze; they do not authorize additional migration, API, new receipt enums or native staging implementation. Once F folds precise choices into the contract, A will review that pinned revision for final scoped ACK.
