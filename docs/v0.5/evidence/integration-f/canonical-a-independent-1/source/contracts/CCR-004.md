# CCR-004 — Product facts for AI speech

## Reason

Go exposes `get_product`, `get_product_stock`, and `get_product_price`, and Runtime has a `ToolClient`, but the current Runtime utterance input contains no product identity or approved tool-call context. The orchestrator never calls the ToolClient. A COMMENT such as “有 XL 吗？” cannot be answered with verified live stock.

## Proposed Change

Define how Go supplies the active product identity and permitted tool context to Runtime for a platform event or utterance. Specify the source of `productId`, behavior when no product is selected or a tool fails, and how retrieved facts enter `SpeechPlan` without changing the existing Tool Result structure. Coordinate with CCR-002's COMMENT input design.

## Impact

- Runtime command/event input schema
- Go LiveRoom or session context and platform event routing
- Runtime tool orchestration and LLM prompt assembly
- Frontend product selection if required by the chosen design
- Contract and end-to-end tests

## Breaking

TBD after choosing whether product context is optional or required.

## Migration

Do not infer a product ID from free text. Freeze the context schema, generate DTOs, then test real stock changes and tool failure behavior before enabling factual answers.
