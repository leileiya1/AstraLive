# CCR-005 — Runtime create-session voice conformance

## Reason

`CreateRuntimeSessionRequest.voice.provider` is required in the frozen OpenAPI, but the real Runtime previously accepted an omitted provider because it reused the Speak voice DTO. The integration Mock already required the field.

Go also previously collapsed valid Runtime `409` error codes to `CONFLICT` and `404` error codes to `SESSION_NOT_FOUND`, obscuring the frozen error enum's specific meaning.

## Proposed Change

No schema change. Use a required-provider DTO for Create Session and retain the existing voice-ID-only DTO for Speak. Add a missing-provider contract regression test.
Preserve recognized Runtime error codes when Go forwards errors to the public API.

## Impact

- Runtime validation and tests
- Backend Runtime error mapping and tests
- No Backend or Frontend wire change

## Breaking

NO relative to the frozen Contract. Invalid requests that previously slipped through now return `422 INVALID_ARGUMENT`.

## Migration

Implemented in Runtime; callers already send `provider`. Keep this CCR as the audit record for the conformance correction.
