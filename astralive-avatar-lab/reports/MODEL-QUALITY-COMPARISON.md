# 模型比较：实测吞吐与待确认视觉

只依据本次真实生成视频与日志；不以官方 RTX4090 宣传数字作为 AstraLive 验收。硬件实际为 RTX4090D 24GB。两个模型的环境按官方依赖隔离，因此不可能全部软件版本相同；GPU、音频、25FPS时间轴、测量脚本/采样周期一致。

## 公平性

默认 MuseTalk 使用 Sun 视频（576×768），SoulX 使用 Girl 图片（512×512）。人物、来源清晰度、构图不同，这组不能评判颜值或做严格视觉胜负结论。MuseTalk 默认只生成256×256口部区域后合成；SoulX生成整幅512×512，核心计算FPS也不能直接排名。

额外同源质量对照：两者均使用同一官方 Girl PNG、同一精确10秒中文 WAV、同一25FPS、512×512。MuseTalk是官方图片Normal模式/FP16，SoulX是常驻stream/BF16。该附加测试对照图像与音频，不把 MuseTalk 的 PNG 落盘冷启动耗时和 SoulX 缓存速度混为公平性能排名。原始编码 preset 不同，未据此做细微纹理定量排名；需要像素级研究时应保留模型原始帧并统一编码。

不标模型名的视频：[A-short.mp4](../outputs/comparison/A-short.mp4)、[B-short.mp4](../outputs/comparison/B-short.mp4)。它们均为实际生成结果的完整副本，带音频，不是宣传片。

## 客观结果

| 维度 | MuseTalk 1.5 | SoulX Lite |
|---|---|---|
| 中文10/30/60秒含编码吞吐 | 35.91/34.95/36.06 FPS | 61.22/63.20/64.55 FPS |
| 预热后首次输出 | 首合成帧120–160ms | 首CPU可用24帧块300–327ms |
| 延迟可直接等同直播响应吗 | 不可；需增量Whisper验证 | 不可；还需积累0.96s音频/块 |
| 自然动作来源 | 使用源视频现有动作/缓存循环；图片对照无自主头部生成 | 模型可生成头部、眼睛与表情变化，抽样实际可见眨眼 |
| Avatar缓存 | 实际复用，同进程连续短句 | 图片/运动latent及常驻模型；不同句测试重置图片状态 |
| 工程问题 | 图片Normal导出后清理变量错误；缓存适配器完成测试 | 依赖版本修复后运行；首次编译首块179s，需预热后发布ready |
| 10分钟稳定性 | 600.112s，15000帧，零丢帧/超40ms迟到 | 600.319s，15000帧，零丢帧/超40ms迟到 |
| 长期视觉漂移 | 源动作循环限制；未做600s动态质量评分 | 600s真实帧开始/中间/结束片段待观看 |

吞吐高不等于视觉真实，更不等于首字响应快。短片中的首帧计时均为离线完整音频提交，未包含网络、业务TTS或远端播放。

## 主观评分与人工验收

视觉真实感、嘴唇/牙齿、音画对应、闪烁、头部跳变、连续性、眨眼自然度均未由 Agent 填写数值评分。基线抽样未见严重五官变形，但不能用静态图证明动态自然度。请先盲看A/B，再观看60秒以及SoulX长期片段，分别记录问题时间点。

用户实际观看同源短片后反馈：**“B-short最自然好看”**。又确认**“soulx-soak-end和soulx-long.mp4能接受很自然”**。B为SoulX Lite，据此将SoulX选为下一阶段Worker首选；不是Agent自行视觉打分。人工确认覆盖同源短片、60秒及600秒末段，不是逐帧审阅整段600秒。

两者官方示例仅按研究输入使用；Sun未证实为真人拍摄，Girl也未取得商业肖像使用确认。模型代码许可证不等于真人肖像权/直播授权。商业个人Avatar另需合法授权素材和单独验收。
