# CCR-003 — WebRTC browser signaling

## Reason

The frozen API has no SDP offer/answer or ICE signaling route. `WebRTCMediaOutput.create_answer()` is only reachable from in-process tests; the frontend preview has no signaling adapter. Browser preview is an explicit v0.1 acceptance condition.

## Proposed Change

Define a Go-owned public signaling endpoint scoped to `sessionId` and a Go-to-Runtime internal signaling endpoint. Specify the request and response fields for SDP type/content, ICE gathering strategy (complete SDP or trickle candidates), authentication/session state checks, error codes, peer lifecycle, and ICE server configuration. Go forwards signaling only; media remains Runtime-to-browser WebRTC.

## Impact

- `contracts/control-api.openapi.yaml`, `contracts/runtime-api.openapi.yaml`
- Backend routing/Runtime client
- Runtime peer creation/cleanup
- Frontend `PreviewSignal` adapter
- Browser integration tests and network configuration

## Breaking

NO. Additive endpoints; existing command and event fields stay unchanged.

## Migration

Approve and freeze the two endpoint schemas, generate clients, implement Go and Runtime signaling, then prove browser audio/video, disconnect cleanup, and Interrupt in both Mock and real modes.
