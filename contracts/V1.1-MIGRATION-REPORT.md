# AstraLive Contract v1.1.0 Migration Report

日期：2026-10-06

## 1. 修改范围

- `architecture/ARCHITECTURE.md`：同步 v0.1 核心验收范围、媒体路径、Session Context、Product Tool、SSE heartbeat 和 Mock parity。
- `contracts/CONTRACTS.md`：冻结 COMMENT 标准化、Context 快照、商品动态事实、non-trickle WebRTC、显式 heartbeat、Mock parity 和 v0.2 deferred 边界。
- `contracts/control-api.openapi.yaml`：组件改名、LiveRoom 可选 `activeProductId`、公共 WebRTC offer/answer、COMMENT 409/202、SSE heartbeat 说明。
- `contracts/runtime-api.openapi.yaml`：必填 Session `context`、必填 Utterance `source`、可选 `platformContext`、内部 WebRTC offer/answer。
- `contracts/examples/*-v1.1.json`：新增五份 Runtime/COMMENT/WebRTC 请求和响应示例。
- `contracts/validate_v1_1.py`：可重复运行的 OpenAPI、JSON Schema、示例和关键必填字段校验。
- `contracts/CHANGELOG.md`：记录 v1.1 变更。既有 `contracts/events/*.json` 的 `schemaVersion=1.0` 与 Tool Result wire format 均未改变。

## 2. CCR 处理

| CCR | 处理结果 |
| --- | --- |
| CCR-001 | `components.requestBodies` 用 `*Body`，`components.responses` 用 `*Result`，不再与 schema 同名；直接以冻结 Control OpenAPI 运行 oapi-codegen 成功。HTTP 路由和已有 JSON 不变。 |
| CCR-002 | COMMENT 使用原公共 dev 路由，由 Go 按 room 找当前 LIVE/DEGRADED Session，标准化为 priority 80 的 PLATFORM_EVENT Utterance，经原 Runtime Speak 路由发送；无活动 Session 为 `409 SESSION_NOT_RUNNING`。Knowledge document/index 和高级 Avatar prepare 的未完成部分移至 v0.2。 |
| CCR-003 | 公共与内部各增加一个 SDP offer/answer 路由；完整 SDP、non-trickle ICE；媒体仅 Browser ↔ Runtime。 |
| CCR-004 | LiveRoom 可选 `activeProductId` 进入 Runtime Session Context；Runtime 按需调用现有 Go Product Tool；无商品或 Tool 失败时不捏造动态事实，失败发布 `RUNTIME_WARNING`。 |
| CCR-005 | 保留历史审计记录；本轮不更改其既有 wire format。 |

## 3. Breaking Change

公共现有 HTTP 路由及已成功的 JSON 载荷没有删除或重命名；WebRTC 路由和 LiveRoom 字段为新增。OpenAPI 组件**符号**更名会影响引用旧组件名的生成器配置，需要重新生成类型。

Go ↔ Runtime 内部命令存在迁移性 breaking change：`CreateRuntimeSessionRequest.context` 与 `RuntimeUtteranceRequest.source` 现为必填。旧 Go 发送端或旧 Runtime 校验器不能直接与 v1.1 内部契约混用，须协调升级。SSE heartbeat 从注释帧改为显式命名帧，监听器需处理新帧；Event Envelope 本身不变。

Contract v1.1 的冻结**不代表**当前 Backend/Runtime/Frontend/Integration 代码已符合它，也不推翻 `RELEASE-CHECKLIST.md` 的 v0.1 NO-GO 判定。

## 4. Backend 迁移

1. 直接从 `contracts/control-api.openapi.yaml` 生成代码，删除对私有改名版 Contract 的依赖并更新生成类型引用。
2. LiveRoom 持久化和返回 `activeProductId`；创建 Runtime Session 时发送 LiveRoom Context 快照，含 `roomId`、`systemPrompt`。
3. dev COMMENT 按 room 找 LIVE/DEGRADED Session，创建普通 Utterance 并转发 `source`/可选 `platformContext`；没有活动 Session 返回 409。
4. 转发公共 WebRTC SDP offer 到 Runtime 并包装 answer；验证 Session 状态和 `WEBRTC_FAILED` 错误映射；不得代理媒体。
5. SSE 发送显式 heartbeat frame 和 UTC timestamp。

## 5. Runtime 迁移

1. 校验、保存 Session Context 快照与 Utterance `source`，接受标准化 `platformContext`；不查询 LiveRoom 数据库或解析平台专有 payload。
2. 根据 `activeProductId` 按需调用现有 Product Tool，把经过验证的事实交给 LLM；缺上下文与调用失败时不猜测，Tool 失败发布 `RUNTIME_WARNING`。
3. 实现内部 SDP offer/answer；等待 ICE gathering 完成后返回 answer，维护 Peer 清理与 `WEBRTC_FAILED`。
4. 保持队列、FIFO、抢占及两个 FSM 与冻结规则一致。

## 6. Frontend 迁移

1. 重新生成 Control API 类型，LiveRoom 配置支持可选 `activeProductId`。
2. WebRTC Preview 通过公共 offer 路由完成 non-trickle SDP 交换，ICE gathering 完成后提交 offer；媒体 Peer 直接连 Runtime。
3. 监听显式 `heartbeat` 并重置 45 秒连接超时；不加入业务 Timeline。
4. COMMENT 的 409/202 响应按普通 Session/Utterance 状态呈现。

## 7. Integration 迁移

1. 两个 Mock Runtime 与 Real Runtime 对齐 Priority Queue、同优先级 FIFO、`NONE`、`INTERRUPT_LOWER_PRIORITY`、`FORCE`、Session FSM、Utterance FSM；补充行为对照测试。
2. 验证 COMMENT → 普通 Utterance → Runtime Event；无活动 Session 为 409；Tool 有商品/无商品/失败场景均不产生虚构库存或价格。
3. 在 Mock 与 Real Runtime 模式执行 Browser SDP 与实际 Audio/Video 预览，校验 Peer 断开清理、Interrupt 和 SSE heartbeat；仅 SDP 经过 Go。
4. 重新完成 Compose、浏览器与一小时验收；语义不同的 Mock 结果不能证明 Real Runtime 通过。

## 8. Contract validation

本机全局 Python 缺少校验包，依赖仅安装在 `/tmp/astralive-openapi-validator`，未修改仓库其他模块：

```sh
python3 -m pip install --target /tmp/astralive-openapi-validator openapi-spec-validator PyYAML jsonschema
PYTHONPATH=/tmp/astralive-openapi-validator python3 contracts/validate_v1_1.py
(cd backend && go run github.com/oapi-codegen/oapi-codegen/v2/cmd/oapi-codegen@v2.5.1 -generate types -package openapi -o /tmp/astralive-control-v1.1.gen.go ../contracts/control-api.openapi.yaml)
(cd backend && go run github.com/oapi-codegen/oapi-codegen/v2/cmd/oapi-codegen@v2.5.1 -generate types -package runtimeapi -o /tmp/astralive-runtime-v1.1.gen.go ../contracts/runtime-api.openapi.yaml)
gofmt -e /tmp/astralive-control-v1.1.gen.go >/dev/null
gofmt -e /tmp/astralive-runtime-v1.1.gen.go >/dev/null
```

结果：两份 OpenAPI 3.0.3 通过 `openapi-spec-validator`，无跨 component 符号重名；三份 Draft 2020-12 Event JSON Schema 及原示例通过；五份 v1.1 DTO 示例通过（分别按 Control/Runtime schema 共校验六次）；Context 必填、Utterance source 必填及非法 source/offer type 的反例校验通过；两份冻结 OpenAPI 直接生成 Go 类型成功，`gofmt` 语法检查通过。未执行各模块实现测试或端到端验收，本轮仅修改架构与 Contract。

## 9. Freeze 决策

**Contract v1.1.0 可以 Frozen**：所要求的跨模块路由、DTO、行为、deferred 范围和机器校验均已明确。**v0.1 产品发布仍 NO-GO**，直到各模块完成本报告迁移并通过 `RELEASE-CHECKLIST.md` 所列浏览器、Tool、Mock parity、Compose 和长时验收。
