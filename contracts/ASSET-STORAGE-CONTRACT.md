# AssetStorage Contract v0.3.1

Status: FROZEN 2026-10-09. This additive contract supplies the missing personal-media boundary. Machine source: `personal-assets/generate_schema.py`; generated OpenAPI: `personal-assets/schema.json`. Implementation coverage is recorded in `PERSONAL-ASSETS-HANDOFF.md`. A frozen interface does not mean its HTTP handler has been deployed. Existing v1.1 and user-config v0.3.0 wire contracts remain unchanged.

## Identity and storage boundary

Every public endpoint below is under `/api/v0.3/config` and uses the existing configuration session adapter: HTTPS, HttpOnly/Secure/SameSite=Strict cookie, server-derived `{tenantId,userId}`, exact Origin for mutations, no-store responses. A same-tenant different user is a different owner. Unknown and cross-owner IDs return the same 404 RESOURCE_NOT_FOUND, including upload, preview, jobs and derived assets. Browser input cannot specify owner, object key, server path, remote URL, worker token or provider secret. No URL-import feature is defined.

AssetStorage stores immutable bytes outside the public web root, using backend-generated opaque keys. The object store/filesystem adapter is replaceable; it is not a second application architecture. PostgreSQL holds metadata/ownership/digests, not the media blobs. Encryption at rest uses the operator's private storage encryption boundary; any per-object encryption key is held outside the media/database and follows SECURITY-BOUNDARY. Originals remain immutable while retained, derivatives reference their source. User input must never form filesystem paths; reject symlink traversal when materializing bytes. The browser never receives object keys, server paths, bucket credentials, signed storage URLs, or internal claim tokens.

`Asset = {assetId,purpose,state,version,byteLength,sha256,mediaType,preprocessingVersion,sourceAssetId?,errorCode,createdAt,consent}`. IDs are opaque bounded strings; SHA256 is 64 lowercase hex characters. On STAGED, byteLength/sha256/mediaType describe the declaration, not validated bytes; only READY marks validated metadata. Public purpose is AVATAR_PHOTO or VOICE_REFERENCE; only a processor may create NORMALIZED_PHOTO, NORMALIZED_AUDIO, AVATAR_PREVIEW or VOICE_PREVIEW. Source and derivative share the exact owner. `preprocessingVersion` is empty until validation; errorCode NONE means no error, not readiness. Receipt `{policyVersion,acceptedAt}` is stamped by Backend, never browser time.

## Upload API and limits

| Method/path | Input | Success |
| --- | --- | --- |
| POST `/asset-uploads` | CreateUpload + Idempotency-Key | 201 UploadTicket `{uploadId,asset,expiresAt}` |
| PUT `/asset-uploads/{uploadId}/content` | raw bytes, application/octet-stream | 204, atomically stored bytes |
| POST `/asset-uploads/{uploadId}/complete` | `{}` | 202 validation Job |
| DELETE `/asset-uploads/{uploadId}` | no body | 204 aborted upload |
| GET `/assets` | no body | owned assets, including terminal states |
| GET `/assets/{assetId}` | no body | Asset |
| DELETE `/assets/{assetId}` | `{expectedVersion}` | 202, DELETING metadata retrievable via GET |
| GET `/assets/{assetId}/preview` | cookie, optional single Range | authenticated safe bytes |
| GET/DELETE `/personal-jobs/{jobId}` | no body | Job / cancelled Job |

CreateUpload is a discriminated union. Photo: purpose AVATAR_PHOTO, declared byteLength 1..10 MiB, JPEG/PNG/WEBP. Audio: purpose VOICE_REFERENCE, byteLength 1..20 MiB, audio/wav, audio/mpeg, audio/ogg, audio/webm, audio/mp4 or audio/flac, plus `referenceText` (trimmed 1..1000 Unicode code points, no NUL). Both require declared sha256 and `consent:{accepted:"PERSONAL_MEDIA_PROCESSING_V1",rightsConfirmed:true}`. Backend requires consent to process the person's image/voice for personal avatar generation and the user's right to supply the material. This is a product acknowledgement, not identity verification or proof of third-party rights. A transcript is private owner data; never log it or attach it to public URLs. Store it encrypted under the external keyring. Upload-time text is passed privately to audio validation; a VoiceProfile may supply a corrected valid transcript without altering the audio bytes.

Upload lease 30 minutes, no chunk/resume protocol in this version. Backend streams with hard byte and concurrency limits, computes digest itself, verifies declared size/digest, and sniffs the actual container. Content-Length is not trusted. Exact repeated PUT with same digest is idempotent; different replacement bytes return 409 CONFIG_VERSION_CONFLICT. Expired lease returns 410 UPLOAD_EXPIRED. Size/digest mismatch returns 422 UPLOAD_SIZE_MISMATCH/UPLOAD_HASH_MISMATCH and deletes temporary bytes. Complete is idempotent and returns the same validation job. Idempotency-Key is scoped by owner + operation + resource and retained 24 hours; same key/different canonical body is 409. No error may return success envelope.

Default per-owner limits: 100 retained source assets, 1 GiB retained bytes including derivatives and reservations, 3 outstanding upload reservations, 2 queued/running processing jobs, 1 queued/running preview. Reserve quotas transactionally before allocating storage; enforce per-tenant aggregate limits through operator policy. These are operator limits, not browser editable. QUOTA_EXCEEDED is 429. Storage failure never commits READY metadata; metadata commit failure triggers staged-object cleanup. The reconciler retries failed deletions and removes expired uploads within 24 hours.

## Validation and lifecycle

Lifecycle: STAGED -> UPLOADED -> VALIDATING -> READY or REJECTED. Abort/expiry enters DELETING -> DELETED. READY/REJECTED can enter DELETING -> DELETED. No external client sets a state, digest, normalized asset ID or validation outcome. READY derivative publication and source validation result are one database transaction after verified output persistence. Retry after failure creates a new processing attempt; original bytes stay unchanged. Reject archives, executable/script content, SVG, animated images, multipart/polyglot payloads and audio containers with non-audio streams. File names and extensions do not authorize formats.

`photo-face512-v1`: decode in an isolated resource-limited processor; source <=10 MiB, one JPEG/PNG/WEBP frame, <=16,000,000 pixels, each dimension >=512. Apply EXIF orientation; exactly one detected face, confidence >=0.9; |yaw|/|pitch| <=15 degrees, |roll| <=10 degrees, eyes and mouth visible; face bounding-box shortest dimension >=192; Laplacian variance >=40 on a 256x256 RGB face crop. A centered square 1.6 times the longer face dimension must fit the source; resize to 512x512 RGB PNG. Reconstruct pixels to strip EXIF/GPS/text/ICC; metadata stripping alone is insufficient. Missing face inspector returns FACE_CHECK_UNAVAILABLE, never an unchecked pass. No face recognition or biometric authentication is defined.

`reference-pcm16k-v1`: <=20 MiB, supported audio-only container, exactly one audio stream, 1 or 2 channels, stable input sample rate 8000..96000 Hz. Bounded decode/resample to mono 16000 Hz signed PCM16 WAV. Final duration 3..30 seconds, RMS >=0.003, clipped-sample fraction <=0.01. Strip container metadata. Validate transcript bounds separately; this does not prove transcript/audio alignment or cloned-voice quality. Failures use the PHOTO_* and REFERENCE_AUDIO_* static codes in the schema. The processor enforces 60-second decode timeout, <=512 MiB memory and <=256 MiB temporary storage, no network, no shell interpolation; reaching a resource limit returns JOB_TIMEOUT or the matching decode error.

## Preview and deletion

Only READY normalized images/audio or generated preview outputs can be previewed. Original photographs/audio never render inline; source preview is 409 ASSET_NOT_READY. Output is image/png, audio/wav or video/mp4 with nosniff, no-store, inline disposition without user filename, no scripts. Single byte Range supports 206 with Content-Range/Accept-Ranges; malformed/multiple/unsatisfiable ranges yield 416 and `Content-Range: bytes */length`. Browser may use an ephemeral Blob URL and must revoke it; no localStorage/IndexedDB/media persistence. Asset preview is a normalization check; it does not assert actual avatar inference or voice cloning succeeded.

Source/derivative deletion checks current profile revisions, defaults, jobs and all live binding leases. Any such reference yields 409 ASSET_IN_USE; user first disables/removes referencing profiles and cancels/releases work. Expired bindings stop authorizing access even before GC. Tombstoned profile history may retain digests but cannot keep an unleased asset accessible forever. Deletion of a source removes its unreferenced derivatives too; reserve/release refcounts under the owner lock. After DELETED, GET metadata is retained for 30 days and preview returns 404; bytes must be erased from active storage. Backups follow an operator retention policy and must not restore user-accessible deleted media. Deletion is retryable and never silently reported as completed while bytes remain.

## Internal AssetStorage and processor protocol

Internal endpoints use a dedicated registered processor bearer identity, bound to allowed workerRef and job kinds. This token is distinct from browser, identity-adapter and control-plane tokens. A caller-supplied scope alone never grants ownership: Backend verifies worker assignment and lease. Tokens are owner-only files, rotated without restart, never query parameters or logs.

1. POST `/internal/v0.3/personal-jobs/{jobId}/claim` `{scope,workerRef}` returns JobClaim with opaque claimToken, attempt, inputAssets, leaseExpiresAt, and only the necessary immutable AvatarProfile/VoiceProfile/previewText/referenceText. Job snapshots freeze version/config at enqueue. Job.action is VALIDATE for source validation, PREPARE for avatar preparation or voice diagnostic synthesis, and PREVIEW for ordinary generated previews; kind/action mismatches are rejected. Validation claims carry the original source descriptor (UPLOADED/VALIDATING is allowed for this one purpose); preparation/preview claims carry only READY normalized inputs. Lease 60s; heartbeat every <=20s through `/heartbeat` `{claimToken,attempt}`. Only one valid attempt at a time; failed/expired attempts cannot commit. Two retries maximum for validation/preparation; preview is never automatically retried (explicit user retry may incur compute). Job deadline: validation 60s, preparation 120s, preview 60s. Queued unclaimed jobs expire in 5 minutes with PROCESSOR_UNAVAILABLE; no processor means prepare/preview fails immediately with 409.
2. GET `/personal-jobs/{jobId}/inputs/{assetId}/content` requires processor bearer + X-Job-Claim. Backend only streams immutable inputAssets of that claim, checks digest, and provides X-Asset-SHA256. No arbitrary path/URL resolve operation. Worker materializes a generated private local path and verifies digest before decoding; paths stay worker-local.
3. POST `/personal-jobs/{jobId}/outputs` with claimToken, attempt, allowed derivative purpose, byteLength, sha256, mediaType reserves an output. X-Job-Claim must equal body token. Then PUT `/personal-output-uploads/{uploadId}/content` streams bytes with bearer + claim header. Output limits <=20 MiB. Backend independently verifies size, digest, media type and immutable lineage. Job kind restricts purpose: VALIDATE_PHOTO -> NORMALIZED_PHOTO PNG; VALIDATE_AUDIO -> NORMALIZED_AUDIO WAV; PREVIEW_AVATAR -> AVATAR_PREVIEW MP4; PREVIEW_VOICE -> VOICE_PREVIEW WAV. PREPARE_AVATAR produces readiness/cache metadata, no downloadable object.
4. POST `/personal-jobs/{jobId}/result` posts SuccessResult or FailureResult. Result kind must equal the claimed kind, output asset must come from this attempt's reservation, normalized dimensions/audio constraints must be checked, source/version/preprocessing values must match immutable inputs. A trusted processor proof is required but does not bypass output checks. Wrong purpose/ownership/digest/attempt returns OUTPUT_INVALID or JOB_CLAIM_EXPIRED. Stale profile version cannot mark the new revision READY (409 CONFIG_VERSION_CONFLICT). Same already-committed result is idempotent; different replay conflicts. Static failure codes only; raw stderr/tracebacks never cross this boundary.

Internal binding asset reads are GET `/internal/v0.3/personal-session-bindings/{bindingId}/assets/{assetId}/content`. Processor identity must be assigned to this binding and asset in its immutable allowlist, binding must be unexpired and unreleased. Public clients cannot call these APIs. AssetStorage's Go interface in `backend/internal/personalconfig/contracts.go` takes typed job/binding authorization; unrestricted `Open(path)` is intentionally absent.

Cancelling a QUEUED/RUNNING job through public DELETE atomically marks CANCELLED and invalidates its claim; every heartbeat/input/output/result operation rechecks cancellation. Assigned workers stop cooperatively and discard uncommitted outputs. Terminal jobs return their unchanged final Job on repeated DELETE; cancellation cannot erase an already completed output or revive a failed job. A disconnected browser does not cancel a job implicitly. Cancelled preparation leaves the current profile FAILED with JOB_CANCELLED; ordinary preview cancellation does not change established readiness. GC deletes abandoned output reservations and releases quota.
