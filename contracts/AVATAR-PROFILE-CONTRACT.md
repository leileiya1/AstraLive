# AvatarProfile Contract v0.3.1

Status: FROZEN 2026-10-09. Machine contract: `personal-assets/schema.json`. Shares the ownership, upload, job and preview rules in ASSET-STORAGE-CONTRACT. Integration status: PERSONAL-ASSETS-HANDOFF. This is an additive personal-avatar entity; it does not redefine the v1.1 avatarId, Runtime Tool API, existing generic Profile/avatarRef, or production default Avatar Provider.

## Entity and capabilities

AvatarProfile is `{avatarProfileId,name,version,state,enabled,isDefault,config,normalizedPhotoAssetId?,readiness?,errorCode,createdAt,updatedAt}`. Config is strictly `{provider:"soulx_lite",photoAssetId,workerProfileId,modelRef:"soulx-flashhead-lite",preprocessingVersion:"photo-face512-v1"}`. photoAssetId must reference the owner's READY AVATAR_PHOTO source with a READY normalized-photo derivative. workerProfileId must reference that owner's enabled generic GPU_WORKER Profile; the profile's logical workerRef must be registered by the operator. An uploaded photo cannot choose a network address, CUDA command, model path, weights revision or mount path. Model registry pins the reviewed revision; no user-directed download or GPU allocation.

All mutations are owner-scoped. Create starts version 1 CREATED; replace config/name increments version and creates a new immutable revision, clears readiness/default and starts CREATED. Unknown fields are 422 INVALID_ARGUMENT. IDs are never reinterpreted as old avatarRef. Existing `avatar_profiles` is a generic SQL view; new physical tables are `personal_avatar_profiles` and `personal_avatar_profile_revisions`. No view replacement or automatic migration of old profiles is authorized.

## Public API

Under `/api/v0.3/config/avatar-profiles`:

| Method/path | Input | Success |
| --- | --- | --- |
| GET collection / GET `/{avatarProfileId}` | cookie | array / AvatarProfile |
| POST collection | `{name,config}` + Idempotency-Key | 201 AvatarProfile |
| PUT `/{avatarProfileId}` | `{expectedVersion,name,config}` | AvatarProfile |
| POST `/{avatarProfileId}/prepare` | `{expectedVersion}` + Idempotency-Key | 202 immutable PREPARE_AVATAR Job |
| POST `/{avatarProfileId}/preview` | `{expectedVersion,audioAssetId}` + Idempotency-Key | 202 PREVIEW_AVATAR Job |
| POST `/{avatarProfileId}/default` | `{expectedVersion}` | AvatarProfile, effect NEXT_SESSION |
| POST `/{avatarProfileId}/disable` | `{expectedVersion}` | DISABLED; clears default |
| DELETE `/{avatarProfileId}` | `{expectedVersion}` | 204 logical tombstone; existing leased revision remains pinned |

Prepare: CREATED/FAILED -> VALIDATING -> PREPARING -> READY or FAILED. Preparation consumes normalized photo plus frozen workerProfile version/model revision, uses the already-authorized registered Worker, and must produce Readiness proof. Repeated prepare of the current READY revision can return its existing successful Job if input digest/model/worker version are identical. A new prepare invalidates current readiness before work begins and clears default. No implicit auto-prepare on upload/create/default.

Readiness `{mode,checkedAt,modelRevision,preprocessingVersion,inputSHA256,cacheId,workerProfileVersion,warmupFrames,encoderReady}` is server/processor produced. REAL, >=3 successfully generated warmup frames and encoderReady=true with matching input/model/worker versions are required for READY/default/session capture. SIMULATION may be reported for diagnostics but cannot mark READY or permit default; error WORKER_NOT_READY. The cache key includes normalized-photo digest, model revision and preprocessing version; `soulx-lite-512-seed42-v1` is the current Worker preprocessing identity, distinct from photo-face512-v1. No cache reuse on identity mismatch. Readiness does not assert GPU benchmark/FPS/long-session acceptance. Worker liveness TTL60s is checked at capture; stale/down worker yields WORKER_NOT_READY even if the profile was previously READY.

Preview requires a READY current avatar revision and the owner's READY NORMALIZED_AUDIO asset, duration <=10 seconds. Backend validates and binds photo/audio/model/worker before enqueue, only an existing authorized Worker is used, and the user action is the compute request. No paid-GPU start, provisioning, model download or production default change. A missing/disabled processor returns 409 PROCESSOR_UNAVAILABLE or WORKER_NOT_READY. A 202 job is pending; only SUCCEEDED plus a verified READY AVATAR_PREVIEW MP4 constitutes successful preview. Failures/cancellation have no fake media or default fallback. Preview output is limited to 20 MiB/10 seconds, valid video + optional audio, no other streams; Backend validates decodability and duration. Asset byte preview rules apply.

DISABLED cannot prepare/preview/default/capture. Explicit PUT is the re-enable operation, creating a fresh CREATED revision with enabled=true; deleted profiles cannot be resurrected. Disabling/tombstoning increments version, clears default, prevents new jobs/bindings, and cancels unleased queued jobs. Already pinned sessions keep the old revision until release/expiry. Any current-version check uses CONFIG_VERSION_CONFLICT; cross-owner uses RESOURCE_NOT_FOUND.

## Internal handoff and effect boundary

Worker consumes JobClaim and input AssetDescriptors, not browser configuration or photo paths. The prepared-result protocol and state-version checks are in ASSET-STORAGE-CONTRACT. Keep neural networks, inference internals and current accepted Session logic owned by the Worker/Runtime agents.

Control plane captures `/internal/v0.3/personal-session-bindings` under a dedicated orchestrator identity, using `{scope,sessionId}` and Idempotency-Key. In ONE owner-locked database transaction, resolve enabled/READY personal defaults, verify real worker readiness, snapshot the selected generic Provider versions and encrypted credentials, create a detached providerBindingId, and capture AvatarProfile/VoiceProfile revisions plus immutable normalized-asset digests. The detached Provider snapshot includes the verified enabled default LLM, settings, the explicit workerProfileId/version selected by this AvatarProfile (not an unrelated GPU_WORKER default), and any explicitly selected LIVE_PLATFORM safe configuration. It excludes generic TTS/AVATAR defaults: personal VoiceProfile/AvatarProfile are the effective TTS/avatar sources for this personal binding; old generic bindings remain unchanged. Conflicting or unavailable capabilities fail capture rather than mixing both selections. Do not call the old provider capture followed by a second separately committed media capture; a concurrent configuration update could mix generations. No public Session request fields or FSM changes are introduced by this contract.

PersonalBinding `{bindingId,sessionId,contractVersion:"0.3.1",avatar:{profileId,version},voice:{profileId,version},providerBindingId,assets,expiresAt}` is internal only. Detached Provider binding uses existing credential encryption rules and is resolved by the authorized control-plane service; browser/asset processor cannot fetch LLM secrets. PersonalBinding assets include the exact normalized-photo/audio and any session-authorized assets, never arbitrary newly uploaded files. Session-only synthesis creates transient PCM under the selected voice revision without silently expanding the asset allowlist. Missing defaults/assets/capabilities prevent capture; no fallback to old experimental keys or different Avatar Provider.

Lease 24 hours from capture/renew. Orchestrator renews at least every hour for long sessions via `/{bindingId}/renew` with scope; renew extends only expiry of the SAME immutable revisions and also its detached provider binding. It never rereads mutable defaults. Renew of expired/released lease returns 410 BINDING_EXPIRED; no resurrection. Stop/error cleanup releases both bindings and asset references through DELETE `/{bindingId}` with scope (idempotent). Private adapters may map binding to the accepted Runtime contract; that integration must pass Session regression before it is enabled. Mid-session config/credential/profile/default updates apply only to the next capture, including when the UI says “current default.”

POST `/internal/v0.3/personal-session-bindings/{bindingId}/resolve` with orchestrator bearer and `{scope}` returns ResolvedPersonalBinding `{binding,avatar,voice,worker:{profileId,version,workerRef}}`. These are the full private snapshots captured at creation, including readiness/normalized IDs and the voice transcript if needed; no filesystem paths, storage keys or Provider secrets. A reference to version N must never resolve to current profile N+1. Config revision payloads are immutable; readiness outcomes are append-only per processing attempt. Capture copies the exact accepted readiness/worker/capability evidence into the private binding snapshot, not a pointer to later mutable readiness. Existing bindings resolve that same snapshot after reprepare/disable/deletion. Orchestrator obtains any LLM credential through separately authorized detached Provider resolution, never exposing it to browser or media processor.
