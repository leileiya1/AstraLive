# Security Boundary v0.3.0

Status: FROZEN 2026-10-09.

Browser -> HTTPS same origin -> Go authenticated scope -> PostgreSQL encrypted credential. Key field is an uncontrolled password input, cleared immediately after submit; no localStorage, persisted query/mutation state, URL, debug logs or server readback. Public readbacks contain credentialConfigured only. All configuration responses no-store. Test prompt/reply is fixed; arbitrary provider response is never returned or logged, including malicious errors that echo keys.

Use Go standard crypto/aes + crypto/cipher AES-256-GCM, CSPRNG unique nonce per encryption. AAD binds tenantId,userId,profileId. Keyring file outside DB/repo, owner-only mode 0600 (reject group/world permissions); `{activeKeyId,keys:{keyId:base64(32 bytes)}}`. Deployment administrator/secret manager controls this file, ordinary users do not. Reload on each operation so credential rotation and master-key activation do not require restart. Retain old key IDs until every credential AND pinned binding is re-encrypted/expired. This release does not auto-delete old keys or provide bulk rewrap; deleting a required key fails closed. Never generate a fallback hardcoded master key. See [Go AEAD documentation](https://pkg.go.dev/crypto/cipher).

Configuration identity cookie: random 256 bits, hashed DB storage, expiry/revocation; trusted login integration provisions claims, no user-controlled X-User headers or common Runtime token shortcut. Separate worker/identity tokens read from operator-controlled files per request, fail closed when unset. Public ingress must block `/internal/v0.3/**`. Worker token grants trusted service privilege, not end-user privilege; compromised trusted worker can access bound credentials and must be isolated. This release does not claim the unauthenticated legacy v1.1 API is SaaS-safe; keep deployment controlled until core ownership is separately migrated.

Custom LLM endpoint: HTTPS only, port 443 only, no userinfo/query/fragment, path empty or /v1; administrators allowlist exact hostnames via CONFIG_LLM_HOSTS. DeepSeek fixed host. Reject IP literals, local/private/reserved/link-local/loopback/multicast/unspecified addresses in IPv4 and IPv6 and all mixed public/private DNS answers. Re-resolve at actual dial, pin selected validated address; TLS ServerName stays original hostname. Disable proxy-from-env and redirects, so keys cannot follow redirects. Block model URL parameters rather than forward arbitrary options. DNS rebinding cannot swap the dial target. Private Worker connectivity is not derived from user URLs: only logical workerRef is stored here.

Bound HTTP/body sizes, deadlines, per-user tests cooldown, no retries or automatic billable tests. Live platform profile is encrypted storage only and no connection probe. Do not initiate paid GPU, modify neural networks/voice cloning, or change production Avatar defaults. Unknown errors become static INTERNAL_ERROR; metadata validation errors are static and do not echo payloads. Never log SQL parameter values, upstream bodies, secrets, raw URLs, Authorization/cookies or binding resolution responses. No secret-request idempotency capture, generic old contract body/error validator, or response-cache middleware on new configuration paths.

Required gates: encryption tampering/ownership AAD; session/CSRF denial; cross-user/tenant isolation; fresh version vs stale test; current credential rotation; DNS/redirect SSRF; metadata leakage; actual PostgreSQL save/read; frontend 401/failed test; original Runtime regression. Real DeepSeek key must be entered via HTTPS webpage, never reused from experiment private storage. Until this happens record REAL_PROVIDER_NOT_VERIFIED.
